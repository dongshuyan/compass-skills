# 证据与推断政策

## 基本规则

把事实、候选人自述、外部佐证、面试表现和推断分别保存。任何高影响判断都必须带原始证据、岗位相关性、置信度、替代解释和验证方法。证据不足时输出“无法判断”，不得把缺失当作负面证据。

本流程不进行人格、心理健康、政治倾向、道德本质或未来行为的诊断，也不根据文字风格、照片、声线、眼神、口音或紧张程度推断能力与品格。

## 基本信息与事实汇总

候选人在获准材料中明确提供的年龄相关出生信息、出生地、籍贯或老家、婚姻状况、现居城市、学校、专业、学历、工作单位、职位、时间和城市属于“候选人自述事实”，可以在候选人简介中直接汇总并保留来源位置。

- 出生日期、出生年月或出生年份可按报告日期换算年龄；日期不完整时标“约”。
- 没有提供的个人事实字段写“未提供”，不从学校、单位、姓名或经历补写出生地、籍贯、老家、婚姻或现居地。年龄可以按下述“履历年龄区间”规则形成单独、显式标注的推算对象，但不能伪装成候选人自述事实。
- 这些基本信息与岗位能力证据分开保存。年龄、出生地、籍贯、老家和婚姻状况不进入人岗匹配、评分、稳定性判断或录用结论。
- 通勤和搬迁只使用候选人明确提供的现居地与公司工作地点，并通过本人确认。

## 简历照片与履历年龄区间

照片和年龄推算属于候选人简介的展示信息，不属于岗位能力证据。

简历照片：

- 只允许使用原始简历 PDF 中视觉确认的候选人个人头像；优先提取独立嵌入图片，否则裁切对应页面。
- `included` 必须保留原始 PDF 哈希、页码、提取方法以及图片索引或裁切框，并校验图片字节、MIME、尺寸和哈希。所有提取结果先统一转换为 PNG 并重新视觉核对；嵌入前在解压前检查尺寸、校验结构和像素数据，并移除非显示所需元数据与文件尾随内容。校验器拒绝 JPEG、损坏图片和未经规范化的负载。
- 无头像、身份含糊或无法可靠提取时分别记录 `not_present`、`ambiguous` 或 `extraction_unavailable`，不从公开主页、搜索结果或其他文件补图。
- 不做人脸识别、身份相似度、年龄、健康、性格、情绪、职业能力或“形象适配”推断。

履历年龄区间：

1. 候选人提供了出生日期、出生年月或出生年份时，按该事实换算年龄，`timeline_age_estimate.status=not_needed`。
2. 没有出生信息时，优先使用简历明确写出的最早本科入学时间。固定假设本科入学年龄为 16–20 岁，典型值 18 岁；年份或月份精度造成的不确定性也计入区间。
3. 没有明确入学时间时，只有同时明确写出本科毕业时间和学制，才能反推本科入学年份。不得自行假设学制，也不得把毕业月份或日期错误继承为入学月份或日期。
4. 研究生入学、工作开始等后续事件只做时间先后核对。它们早于本科锚点时记 `timeline_conflict` 并取消数值区间，不能被当作新的年龄锚点。
5. 没有合格锚点时记 `insufficient_evidence`，不输出数值。所有数值结果都必须写明“推算”和“非候选人自述”，并保存截止日、来源位置、锚点精度和假设。
6. 推算区间不得进入人岗匹配、简历疑点优先级、题目评分参考、稳定性判断、录用/淘汰结论或候选人排序。

## STAR-O-V 证据单元

把每条简历声明、公开职业成果或面试回答拆成：

- `Situation`：发生背景和约束。
- `Task`：候选人需要完成的任务。
- `Action`：候选人本人采取的行动和决策。
- `Result`：结果、基线、指标口径和时间窗口。
- `Ownership`：个人、团队和他人的贡献边界。
- `Verification`：作品、代码、论文、专利、推荐人或后续问题。

最小字段还应包括原文摘录、页码/章节、时间、组织、规模、使用方法、保密限制、对应岗位任务、证据来源和剩余缺口。

## 证据状态

- `externally_corroborated`：可靠的一手公开来源支持核心事实。
- `strong_self_report`：STAR-O-V 较完整，但仍只有候选人自述。
- `partially_specified`：部分明确，贡献、尺度、指标或验证项缺失。
- `claim_only`：只有技能词、头衔或笼统成果。
- `contradicted`：可靠来源与核心声明存在明确冲突。
- `indeterminate`：信息不足或来源冲突尚未解决。

避免使用“造假概率”“注水百分比”。把风险写成可核验缺口，例如个人贡献边界不清、指标缺基线、团队结果写成个人结果、项目无可复核产物或时间线冲突。

## 分离四类置信度

分别记录，不得互相替代：

1. `extraction_confidence`：是否正确读出了材料内容。
2. `mapping_confidence`：内容是否确实对应目标岗位能力。
3. `truth_status`：自述、已佐证、矛盾或无法判断。
4. `ability_confidence`：现有证据对能力水平的支持程度。

高提取置信度不代表声明真实；声明真实也不自动证明达到岗位目标级别。

## 九类目标的行为化

只分析岗位相关的可观察行为：

| 用户关注点 | 允许形成的行为假设 |
|---|---|
| 三观、人品 | 诚实说明局限、责任归属、错误上报、安全公平取舍、尊重异议 |
| 专业能力 | 在明确约束下完成关键任务并产出可复核结果 |
| 沟通表达 | 澄清需求、解释依据、适配受众、倾听并修正理解 |
| 人际协作 | 分享信息、处理分歧、给出反馈、跨团队推进与关系修复 |
| 事业心、稳定性 | 职业目标、愿意投入的条件、离开风险和岗位预期匹配 |
| 认真负责 | 承诺管理、质量检查、风险升级、纠错和复盘 |
| 薪酬待遇观 | 对薪酬、公平、成长、强度、稳定和自主性的取舍 |
| 候选人关注点 | 从经历选择形成多种假设，并由本人确认 |
| 压力表现 | 优先级、风险分级、沟通升级、资源协调和事后恢复学习 |

稳定性只输出“可能留下/离开的条件及未知项”，不得预测会工作几年。短任期和工作年限只生成核验问题，不直接扣分。

婚姻状况问题仅用于记录候选人自愿提供的信息，不用于推断稳定性、投入程度、出勤、搬迁意愿或未来离职风险。真正与岗位有关的时间和地点条件应直接提问。

## 候选人视角

对每个简历写法或经历选择至少提出两个解释，其中至少一个是善意替代解释。记录：

```yaml
cue: 可观察线索
possible_explanations: [主要解释, 善意替代解释]
evidence_for: []
evidence_against: []
job_relevance: 直接说明
confidence: low|medium|high
what_would_falsify_it: 可推翻信息
neutral_verification_question: 中性问题
prohibited_inference: 不得推出的结论
```

例如“技术细节少”可能来自贡献有限、面向管理岗位压缩、保密要求或简历写作能力较弱。没有进一步证据时保持多种解释。

## 评分资格

- 简历只形成独立的材料证据分或清晰度，不进入综合面试分。
- 公开职业证据只能佐证事实，不能替代共同核心面试题。
- 社交媒体内容不得产生数值分。
- 只有在标准化条件下观察到的共同核心回答或工作样本才进入综合面试分。
- 高影响矛盾尚未解决时显示冲突和待核验，不自动录用或淘汰。
