## 评分目的

评分用于把面试官记录的岗位相关证据结构化。分数必须与行为锚点、候选人原话或工作样本表现一起保存。单个数字不能替代证据说明和人工判断。

同一岗位和级别的候选人使用相同共同核心题、顺序、时间、权重和评分锚点。个性化简历核验题用于确认声明，默认不进入跨候选人比较。

本文件中的分数、权重、覆盖率、门槛和可比性都属于后台审计数据。面试官 HTML 不显示这些内部指标，只显示通俗的回答判断参考和简化记录按钮。

## 进入综合分的条件

一个问题只有同时满足以下条件才进入面试综合分：

1. `scored` 为 `true`。
2. `asked` 为 `true`。
3. `score` 是 1–5 的整数。
4. `human_confirmed` 为 `true`。
5. `weight` 大于 0。

任何条件不满足时，该题在当前计算中为 `null`，并从分子、当前已回答权重分母中同时排除。未问、未回答或未确认均不计为零分。

建议保存原始状态，不要为了计算把 `null` 改写成 0。

评分状态必须携带与蓝图完全一致的 `case_id` 和 `blueprint_version`，并为蓝图中的每个问题保留一个回答项。案件、版本或题目 ID 集合不一致时拒绝计算，防止跨候选人或跨题本静默混分。

## 面试综合分与共同核心分

把 1–5 分线性映射为 0–100：

```text
normalized_i = (score_i - 1) / 4
```

面试综合分：

```text
InterviewComposite =
  100 * sum(weight_i * normalized_i) / sum(weight_i)
```

求和范围仅包含满足“进入综合分的条件”的题目。没有任何合格题目时输出 `null`。后台结果保留一位小数；同一文件中的精度保持一致。

共同核心分使用同一公式，但求和范围进一步限定为 `core=true` 的题目：

```text
CoreScore =
  100 * sum(core_weight_i * normalized_i) / sum(answered_core_weight_i)
```

共同核心题尚未全部完成人工确认时，后台可以计算“当前核心分”，但必须同时保留共同核心覆盖率。只有共同核心覆盖达到蓝图要求时，才可把该分数标为同岗位同蓝图内可比较。

示例：两个已确认问题的权重分别为 2 和 1，得分为 5 和 3：

```text
100 * (2 * 1.0 + 1 * 0.5) / 3 = 83.3
```

## 覆盖率

### 总覆盖率

计划权重包含所有 `scored=true` 且 `weight>0` 的问题：

```text
Coverage =
  100 * answered_confirmed_weight / planned_scored_weight
```

若没有计划评分题，输出 `null`。覆盖率衡量“按计划获得了多少已确认评分证据”，不衡量候选人能力。

### 共同核心覆盖率

共同核心计划权重包含所有同时满足 `scored=true`、`core=true`、`weight>0` 的问题：

```text
CoreCoverage =
  100 * answered_confirmed_core_weight / planned_core_weight
```

若没有共同核心题，输出 `null` 并记录“未配置共同核心”。共同核心题应对同岗位同级别候选人保持一致。

### 个性化问题

个性化简历核验题设置 `core=false`，通常设置 `scored=false`。如果招聘团队确需计分，应事先固定其评分含义；它仍不得改变共同核心覆盖率。

## 门槛状态

门槛题由 `gate=true` 标识。每题可设置 `gate_threshold`，默认值为 3。

状态规则：

- `not_configured`：不存在门槛题。
- `insufficient_evidence`：存在门槛题，但至少一题未问、未评分或未人工确认。
- `threshold_not_met`：至少一个已有合格评分的门槛题低于其阈值。
- `threshold_met`：所有门槛题均有合格评分，且均达到各自阈值。

`threshold_not_met` 是结构化证据状态，不是自动淘汰指令。人工复核人需检查题目质量、合理便利、记录和替代证据。

## 可比性

面试蓝图把 `scoring.comparability_core_coverage_min` 固定为 1.0。共同核心必须全部完成人工确认，才可把共同核心分标为同岗位、同蓝图内可比较。

分别判断共同核心分和含可选题的面试综合分：

- `not_configured`：没有共同核心题。
- `insufficient_core_coverage`：共同核心覆盖率低于最低要求。
- `gate_evidence_incomplete`：共同核心达到要求，但门槛题证据不足。
- `core_comparable_composite_incomplete`：共同核心达到要求且门槛证据完整；共同核心分可比，但总计划覆盖率不足 100%，含可选题的面试综合分仍不可比。
- `all_planned_comparable`：共同核心达到要求、门槛证据完整且总计划覆盖率为 100%；共同核心分与含可选题的面试综合分均可在同岗位同蓝图内比较。

共同核心完整只支持共同核心分的可比性。包含可选计分题的动态面试综合分只有在所有计划计分题均完成人工确认，即总覆盖率为 100% 时才可比。“可比较”不授权自动排名，也不消除面试误差和人工偏差。

导出时保存 `blueprint_version` 和题目 ID 集合；蓝图版本不同不得宣称严格可比。

## 简历证据分

`resume.evidence_score` 是 0–100 的可选值，用于表达材料对岗位声明的支持和完整程度。它必须满足：

- 在后台单独保存，不显示在主 HTML。
- 标为材料证据分或简历证据分。
- 不进入 `InterviewComposite`。
- 不因简历空白自动扣分。
- 不把写作质量当作能力或真实性。
- 与具体证据项、缺口和核验问题共同解释。

若没有经过组织确认的简历证据评分规则，使用 `null`，后台保留材料状态分布即可。

## 行为锚点

每个计分题至少提供 1、3、5 分锚点：

- 1 分：没有展示关键行为，或展示会造成明显岗位风险的处理方式。
- 3 分：在常见情境中展示达到岗位基本要求的行为，有合理但有限的证据。
- 5 分：在复杂约束下展示稳定、可迁移、可复核的高水平行为，并能说明权衡与结果。

锚点必须针对该题测量的具体能力重写，避免使用“感觉好”“气场强”“像我们的人”等主观标签。2 分和 4 分表示介于相邻锚点之间，面试官仍需记录证据。

追问只用于澄清情境、本人行动、结果、贡献边界和复盘。不得对不同候选人使用明显不同难度的引导式追问。

## 面试官视图中的简化记录

岗位题在 HTML 中只显示四种选择：

- `未问` → 后台 `asked=false`、`score=null`；
- `好` → 后台审计映射为 5 分；
- `一般` → 后台审计映射为 3 分；
- `差` → 后台审计映射为 1 分。

选择“好、一般、差”表示面试官已经作出当前人工记录；导出时仍需保留具体备注。2 分和 4 分只在需要更细粒度的后台复核时由有权限的人补充，不增加到主页面。

地点、到岗、个性化安排和候选人自述题使用 `record_only`，只记录“未问、已记录、不便回答”，`score` 始终为 `null`，不进入分数、覆盖率或门槛。婚姻状况题必须属于此类。

面试官页面不显示综合分、共同核心分、权重、覆盖率、门槛或可比性。隐藏这些指标不改变后台公式和共同核心一致性要求。

## 输出字段

HTML 导出的面试记录至少包含：

```json
{
  "schema_version": "1.0.0",
  "case_id": "case-id",
  "blueprint_version": "1.0.0",
  "candidate_name": "候选人姓名",
  "exported_at": "2026-08-04T12:00:00.000Z",
  "questions": {
    "q-core-1": {
      "order": 1,
      "question": "可直接照读的问题",
      "evaluation_mode": "rated",
      "highlight": "must",
      "result": "good",
      "audit_score": 5,
      "notes": "候选人的具体回答"
    }
  }
}
```

模板使用以 `case_id` 隔离的 `localStorage` 保存重点标记、结果和备注，刷新或重新打开同一报告时恢复。导出是当前本机状态的快照。模板不使用 Cookie 或网络请求；本地存储不可用时仍允许使用和导出。

## 实现测试

至少覆盖以下测试：

1. 全部未问：综合分为 `null`，覆盖率为 0。
2. 已问但未评分：该题保持 `null`，不进入分母。
3. 已评分但未确认：该题不进入分母。
4. 两题不同权重：按公式得到正确加权结果。
5. 跳过一题：综合分按已确认题重算，覆盖率下降。
6. 简历证据分变化：面试综合分保持不变。
7. 共同核心未完成：可比性为 `insufficient_core_coverage`。
8. 共同核心已完成但可选计分题未完成：核心分可比，综合分不可比。
9. 所有计划计分题完成：核心分和综合分均可在同岗位同蓝图内比较。
10. 门槛题低于阈值：状态为 `threshold_not_met`，界面不输出自动淘汰结论。
11. 门槛题未完成：状态为 `insufficient_evidence`。
12. 简化记录：好/一般/差分别导出 5/3/1，未问导出 `null`。
13. 自述题：已记录或不便回答都不产生分数。
14. 本地恢复：重点、结果和备注刷新后恢复，其他案件的记录不串用。
15. 重置：所有交互记录恢复为空，嵌入的报告内容保持不变。
